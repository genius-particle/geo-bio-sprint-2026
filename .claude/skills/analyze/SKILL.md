# analyze — OCR + 分析错题

## 触发条件

用户说「分析题目」「解析错题」「处理 pending 题目」时触发。

## 工作流

### 第一步：扫描待分析题目

1. 扫描 `data/questions/` 目录下所有子目录
2. 读取每个子目录中的 `meta.json`
3. 筛选 `analysis_status === "pending"` 的题目
4. 如果没有 pending 题目，告知用户「所有题目已分析完毕」并结束

### 第二步：逐题分析

对每道 pending 题目执行以下流程：

**a. 读取图片**

- 检查题目目录下的图片文件数量
  - 优先查找 `image-1.jpg`, `image-2.jpg`, ... （多图格式，按 `meta.json` 中 `image_count` 字段确定数量）
  - 如果不存在 `image-1.jpg`，回退查找旧格式的 `image.jpg`（单图兼容）
- **如果有多张图片，必须全部读取并作为同一道题一起分析**
- 使用 Claude 视觉能力依次查看所有图片内容
- 多张图片属于同一道题的不同部分（如跨页、正反面），需要整体理解上下文后统一分析

**b. OCR 识别**

- 从图片中提取完整题目文字
- **区分印刷体与手写批注**：图片中可能存在学生或老师用红笔/蓝笔手写的批改痕迹。OCR 时必须明确区分哪些是印刷题干文字、哪些是手写批注
- 将识别结果写入 `meta.json` 的 `ocr_text` 字段（仅记录印刷体文字）
- 如果图片模糊或文字不完整，标记 `ocr_quality: "partial"` 并在分析中注明

**⚠️ 手写批注不可信赖原则**

试卷上的手写批改（红笔、蓝笔等）可能存在以下问题：
- 手写体字迹潦草，OCR 识别准确率远低于印刷体
- 批改本身可能有误（学生错误修改）
- 批改内容可能只是部分修正，不代表完整正确答案

因此：
1. **答案推导必须以印刷题干/材料内容为主**——印刷文字中已包含答题所需的关键信息（如材料中写明「电费低至每度电3美分」，则答案应包含「电费低」）
2. **手写批注仅作辅助参考**——如果手写内容与印刷内容推导的答案一致，可增强信心；如果冲突，以印刷内容推导为准
3. **禁止将手写批注作为答案的唯一来源**

**c. 题型识别**

判断题型并写入 `meta.json` 的 `question_type` 字段，可选值（**必须使用英文枚举值，不要写中文**）：

- `choice`：有明确选项（A/B/C/D）
- `fill`：包含空格或横线待填
- `map`：包含地图、图表、示意图等需要读图
- `judge`：要求判断对错
- `essay`：需要开放性作答
- `mixed`：综合题，包含多种题型

**d. 按题型分析（印刷内容推导优先）**

分析答案时，必须先从印刷题干/材料中提取关键信息来推导答案，再结合学科知识完善。

**推导流程**：
1. **提取印刷材料中的关键事实**——材料文本通常已包含答案线索（如「电费低至每度电3美分」→ 优势条件含「电费低」）
2. **结合学科知识和课本结论推导完整答案**——用材料事实 + 课本知识共同确定答案
3. **手写批注仅作参考**——如果手写内容与推导结果一致，可确认；如果冲突，以推导为准
4. **答案中的每一条都要有印刷材料或课本知识的明确依据**

根据题型走不同分析流程：

- **选择题**：识别所有选项 → 从材料和课本知识判断正确答案 → 逐项解析每个选项对错原因
- **填空题**：识别空位位置 → 从材料中找答案线索或用课本知识推导 → 解释填空依据和原理
- **读图题**：描述图片内容和关键要素 → 分析地理/生物要素 → 逐步解答
- **判断题**：给出对错判断 → 引用课本知识点作为依据
- **简答题**：给出参考答案要点 → 解析答题思路和得分点

**e. 生成结构化分析**

将分析结果写入 `meta.json` 的 `analysis` 字段，结构如下：

```json
{
  "answer": "正确答案",
  "explanation": "详细解析文字",
  "key_concept": "核心知识点名称",
  "common_mistakes": ["常见错误1", "常见错误2", "常见错误3"],
  "related_topics": ["相关知识点1", "相关知识点2"]
}
```

字段说明：
- `answer`：简洁的正确答案
- `explanation`：详细解析，面向八年级学生，通俗易懂，300字以内
- `key_concept`：本题考查的核心知识点
- `common_mistakes`：2-3条学生常犯错误
- `related_topics`：相关联的知识点，便于后续关联学习

**f. 视觉-语义二次校验**

在 2e 之后、2g 之前执行。用结构化推理反向验证直觉识别结果。

**策略 A：读图数值推算**（仅 `map` / `mixed` 且涉及数值读取时）

1. 重新审视图片，只看图例、等高距标注、坐标轴刻度，记录识别结果
2. 找到图中明确标注的数值作为参照点
3. 从参照点按间隔推算目标值：`目标值 = 参照值 ± (间隔 × 格数)`
4. 与 2d 中直接读取的值对比：偏差 > 1 个间隔 → 以推算值为准修正 answer/explanation

**策略 B：语义校验**（所有题型）

- **术语校验**：ocr_text 中的术语与原图文字逐一对照，以原图为准（不是替换为"标准术语"）
- **语法匹配**：每个填空答案的词性/类别应与空位上下文匹配
- **数值合理性**：answer/explanation 中的数值应在学科合理范围内（海拔 200~8848m、年降水 100~3000mm、气温 -40~45°C 等）

**策略 C：手写批注交叉验证**（图片中存在手写批注时）

1. **识别手写内容**：尝试辨认手写批注的文字，但标注为「低置信度识别」
2. **与印刷推导结果对比**：
   - 手写内容与印刷推导一致 → 增强 confidence，在 verification_notes 中记录「手写批注与推导一致」
   - 手写内容与印刷推导冲突 → **以印刷推导为准**，在 verification_notes 中记录分歧（如「手写批注识别为 X，但印刷材料明确指出 Y，以印刷材料为准」）
   - 手写内容无法辨认 → 忽略，不纳入答案，verification_notes 记录「存在手写批注但无法辨认，已忽略」
3. **禁止行为**：不得将无法清晰辨认的手写文字作为答案写入 analysis.answer

**置信度判定**：
- 全部通过，无修正 → `confidence: "high"`, `needs_manual_review: false`
- 有问题但已修正 → `confidence: "medium"`, `needs_manual_review: false`，notes 记录修正内容
- 有无法解决的矛盾 → `confidence: "low"`, `needs_manual_review: true`，notes 详细记录分歧

low 不阻止写入，仅标记提示人工复核。

**g. 更新 meta.json**

更新以下字段：
- `analysis_status`: `"pending"` → `"analyzed"`
- `chapter`: **必须保留**原有 chapter 字段值（录入时已设置），不得删除或留空。如果原 meta.json 中无 chapter 字段，则读取 `data/chapters.json`，用 `knowledge_points` 与各章节的 `points` 匹配，取匹配度最高的章节的 `chapter` 完整名写入
- `knowledge_points`: 从分析中提取的知识点标签数组
- `difficulty`: `"easy"`（简单）/ `"medium"`（中等）/ `"hard"`（困难）
- `analyzed_at`: 当前时间戳（ISO 8601 格式）
- `confidence`: 二次校验的置信度（`"high"` / `"medium"` / `"low"`）
- `needs_manual_review`: 置信度为 `"low"` 时为 `true`，否则为 `false`
- `verification_notes`: 校验备注文字（high 时可写 `"两轮校验通过，无可疑分歧"`）

**重要**：更新 meta.json 时必须完整保留所有已有字段（如 `chapter`、`source`、`source_detail`、`is_mistake` 等），只更新/新增上述列出的字段，绝不允许因重写而丢失原有数据。

**h. 更新错题记录**

如果 `data/mistakes/{id}.json` 存在（即该题目标记为错题），**必须**更新以下字段：

- `correct_answer`: 填入 `analysis.answer` 中的正确答案
- `mistake_type`: 根据分析结果判断错因（`"knowledge_gap"` 知识盲区 / `"careless"` 粗心 / `"misunderstood"` 理解偏差 / `"other"` 其他）
- 其余字段（`review_count`、`next_review_at`、`is_mastered` 等）保持不变

如果 `data/mistakes/{id}.json` 不存在（非错题），跳过此步骤。

**i. 创建/更新 Wiki 页面**

- 检查 `data/wiki/` 下是否存在对应知识点的页面
- 如果不存在，创建新的 Wiki 页面文件
- 如果已存在，将本题作为该知识点的例题补充进去

### 第三步：汇报结果

分析完成后输出统计：
- 分析了 X 道题目
- 新增 Y 个知识点 Wiki 页面
- 按学科分类列出各题型数量

#### 低置信度题目提示

如果本次分析中存在 `confidence` 为 `"low"` 或 `"medium"` 的题目，额外输出以下内容：

1. **低置信度汇总**：
   ```
   ⚠️ 以下题目需要关注：
   - [题目ID] 题型:map | confidence:low | 原因: 隧道口海拔直接读取与推算值矛盾
   - [题目ID] 题型:fill | confidence:medium | 原因: OCR术语修正「降雨量」→「降水量」
   ```

2. **复核指引**：
   - 告知用户：「其中 X 道题目置信度为 low，已标记 needs_manual_review，建议人工复核。」
   - 「Y 道题目置信度为 medium，已自动修正，无需操作但请留意。」
   - 「复核后请编辑 meta.json 将 needs_manual_review 改为 false，confidence 改为 high。」

3. **medium 题目**：仅列出提醒，不要求必须复核。

## 学科特定分析要求

### 地理题目

- **注重读图能力**：对读图题要详细解读图表中的地理信息
- **注重空间思维**：说明地理位置、空间分布、区域特征
- **注重因果关系**：解释地理现象的前因后果（如气候成因、地形影响）
- 常见题型：气候类型判读、地形图分析、区域特征比较、人口/经济数据分析

### 生物题目

- **注重概念理解**：准确定义生物学术语和概念
- **注重结构功能关系**：解释生物结构与其功能之间的对应关系
- **注重实验思维**：涉及实验设计、变量控制、实验结论推导
- 常见题型：细胞结构识别、生理过程分析、遗传概率计算、生态系统分析

### 通用要求

- 解析语言通俗易懂，适合八年级学生阅读理解
- 避免过于学术化的表述，必要时用生活化的比喻帮助理解
- 不使用 Tesseract.js 或任何前端 OCR 工具，全部由 Claude 视觉能力完成

### 填空空位-答案一致性校验（质量门禁）

**适用范围：任何题型**（填空题、读图题、综合题、简答题等），只要 OCR 文本中出现 `______`、`________`、横线填空、①②③ 编号填空等模式，都必须执行以下校验。

**校验步骤（写入 meta.json 前必须完成）**：

1. **数空位**：仔细数出每个子问题中的空位数量（注意区分：①②③ 各算一个空位；连续下划线算一个空位；"对比分析...原因：______"这种末尾填空也算一个空位）
2. **数答案**：数出 `analysis.answer` 中每个子问题对应的答案数量
3. **比对**：每个子问题的空位数必须等于答案数
4. **不一致时的处理**：
   - 如果答案少了 → 补充缺失的空位答案
   - 如果答案多了 → 检查是否把多个空位合并为一个答案，拆分后重新比对
   - 如果空位本身可能是 OCR 误识别（图片模糊导致多识别了空位）→ 以题目语义为准，在 `analysis.answer` 中注明「注：该子问题实际只有 X 个空位」
5. **通过标准**：所有子问题的空位数 = 答案数，否则不允许将 `analysis_status` 设为 `analyzed`，应重新检查并修正

**自检清单（写入前逐条确认）**：
- [ ] 每个子问题的空位是否逐一数过？
- [ ] 每个子问题的答案是否与空位一一对应？
- [ ] 有没有因为答案合并或省略导致的数量不匹配？
- [ ] 空位识别是否与题目语义一致（而非机械匹配下划线）？

### JSON 有效性校验（质量门禁）

**写入 meta.json 前必须完成**：

1. **引号转义**：所有文本字段（`ocr_text`、`answer`、`explanation`、`common_mistakes` 等）中的 ASCII 双引号 `"` 必须转义为 `\"`，或替换为中文智能引号 `""`（推荐后者，更自然）
2. **常见易错字符**：
   - `"人"字形` → `"“人”字形`（中文智能引号）
   - `"西岸"或"东岸"` → `"“西岸”或“东岸”`
   - 题目原文中的引号内容一律用中文智能引号 `""` 包裹
3. **写入后验证**：写入 meta.json 后，**必须读取文件并验证 JSON 有效性**（可用 `node -e "JSON.parse(require('fs').readFileSync('path','utf8'))"` 或 `python3 -c "import json; json.load(open('path'))"` 验证）
4. **无效处理**：如果 JSON 验证失败，不得标记为 `analyzed`，应修复后重试

## 规则

1. **不修改原始图片**：只读取和识别，不对 image 文件做任何改动
2. **保留原始结构**：meta.json 中已有字段不要删除，只更新和新增
3. **批量处理**：如果 pending 题目超过 5 道，提示用户确认是否全部处理
4. **错误处理**：如果某道题目分析失败，标记 `analysis_status: "error"` 并记录原因，继续处理下一道
5. **学科识别**：通过 `meta.json` 中的 `subject` 字段（`geography`/`biology`）判断学科，据此调整分析策略
6. **中文输出**：所有分析内容、OCR 文字、Wiki 内容均使用中文
7. **JSON 有效性**：每次写入 meta.json 后必须验证 JSON 可解析，未通过验证的文件不允许标记为 `analyzed`
8. **错题记录必须更新**：如果 `data/mistakes/{id}.json` 存在，分析完成后必须更新 `correct_answer` 和 `mistake_type`，不得跳过
