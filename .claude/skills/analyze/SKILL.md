# analyze — OCR + 分析错题

## 触发条件

用户说「分析题目」「解析错题」「处理 pending 题目」时触发。

## 工作流

### 第一步：扫描待分析题目

1. 扫描 `data/questions/` 目录下所有子目录
2. 读取每个子目录中的 `meta.json`
3. 筛选 `analysis_status === "pending"` 的题目
4. 如果没有 pending 题目，告知用户「所有题目已分析完毕」并结束

### 第二步：逐题分析

对每道 pending 题目执行以下流程：

**a. 读取图片**

- 检查题目目录下的图片文件数量
  - 优先查找 `image-1.jpg`, `image-2.jpg`, ... （多图格式，按 `meta.json` 中 `image_count` 字段确定数量）
  - 如果不存在 `image-1.jpg`，回退查找旧格式的 `image.jpg`（单图兼容）
- **如果有多张图片，必须全部读取并作为同一道题一起分析**
- 使用 Claude 视觉能力依次查看所有图片内容
- 多张图片属于同一道题的不同部分（如跨页、正反面），需要整体理解上下文后统一分析

**b. OCR 识别**

- 从图片中提取完整题目文字
- 将识别结果写入 `meta.json` 的 `ocr_text` 字段
- 如果图片模糊或文字不完整，标记 `ocr_quality: "partial"` 并在分析中注明

**c. 题型识别**

判断题型并写入 `meta.json` 的 `question_type` 字段，可选值：

- `选择题`：有明确选项（A/B/C/D）
- `填空题`：包含空格或横线待填
- `读图题`：包含地图、图表、示意图等需要读图
- `判断题`：要求判断对错
- `简答题`：需要开放性作答

**d. 按题型分析**

根据题型走不同分析流程：

- **选择题**：识别所有选项 → 判断正确答案 → 逐项解析每个选项对错原因
- **填空题**：识别空位位置 → 给出正确答案 → 解释填空依据和原理
- **读图题**：描述图片内容和关键要素 → 分析地理/生物要素 → 逐步解答
- **判断题**：给出对错判断 → 引用课本知识点作为依据
- **简答题**：给出参考答案要点 → 解析答题思路和得分点

**e. 生成结构化分析**

将分析结果写入 `meta.json` 的 `analysis` 字段，结构如下：

```json
{
  "answer": "正确答案",
  "explanation": "详细解析文字",
  "key_concept": "核心知识点名称",
  "common_mistakes": ["常见错误1", "常见错误2", "常见错误3"],
  "related_topics": ["相关知识点1", "相关知识点2"]
}
```

字段说明：
- `answer`：简洁的正确答案
- `explanation`：详细解析，面向八年级学生，通俗易懂，300字以内
- `key_concept`：本题考查的核心知识点
- `common_mistakes`：2-3条学生常犯错误
- `related_topics`：相关联的知识点，便于后续关联学习

**f. 更新 meta.json**

更新以下字段：
- `analysis_status`: `"pending"` → `"analyzed"`
- `knowledge_points`: 从分析中提取的知识点标签数组
- `difficulty`: `1`（简单）/ `2`（中等）/ `3`（困难）
- `analyzed_at`: 当前时间戳（ISO 8601 格式）

**g. 创建/更新 Wiki 页面**

- 检查 `data/wiki/` 下是否存在对应知识点的页面
- 如果不存在，创建新的 Wiki 页面文件
- 如果已存在，将本题作为该知识点的例题补充进去

### 第三步：汇报结果

分析完成后输出统计：
- 分析了 X 道题目
- 新增 Y 个知识点 Wiki 页面
- 按学科分类列出各题型数量

## 学科特定分析要求

### 地理题目

- **注重读图能力**：对读图题要详细解读图表中的地理信息
- **注重空间思维**：说明地理位置、空间分布、区域特征
- **注重因果关系**：解释地理现象的前因后果（如气候成因、地形影响）
- 常见题型：气候类型判读、地形图分析、区域特征比较、人口/经济数据分析

### 生物题目

- **注重概念理解**：准确定义生物学术语和概念
- **注重结构功能关系**：解释生物结构与其功能之间的对应关系
- **注重实验思维**：涉及实验设计、变量控制、实验结论推导
- 常见题型：细胞结构识别、生理过程分析、遗传概率计算、生态系统分析

### 通用要求

- 解析语言通俗易懂，适合八年级学生阅读理解
- 避免过于学术化的表述，必要时用生活化的比喻帮助理解
- 不使用 Tesseract.js 或任何前端 OCR 工具，全部由 Claude 视觉能力完成

### 填空空位-答案一致性校验（质量门禁）

**适用范围：任何题型**（填空题、读图题、综合题、简答题等），只要 OCR 文本中出现 `______`、`________`、横线填空、①②③ 编号填空等模式，都必须执行以下校验。

**校验步骤（写入 meta.json 前必须完成）**：

1. **数空位**：仔细数出每个子问题中的空位数量（注意区分：①②③ 各算一个空位；连续下划线算一个空位；"对比分析...原因：______"这种末尾填空也算一个空位）
2. **数答案**：数出 `analysis.answer` 中每个子问题对应的答案数量
3. **比对**：每个子问题的空位数必须等于答案数
4. **不一致时的处理**：
   - 如果答案少了 → 补充缺失的空位答案
   - 如果答案多了 → 检查是否把多个空位合并为一个答案，拆分后重新比对
   - 如果空位本身可能是 OCR 误识别（图片模糊导致多识别了空位）→ 以题目语义为准，在 `analysis.answer` 中注明「注：该子问题实际只有 X 个空位」
5. **通过标准**：所有子问题的空位数 = 答案数，否则不允许将 `analysis_status` 设为 `analyzed`，应重新检查并修正

**自检清单（写入前逐条确认）**：
- [ ] 每个子问题的空位是否逐一数过？
- [ ] 每个子问题的答案是否与空位一一对应？
- [ ] 有没有因为答案合并或省略导致的数量不匹配？
- [ ] 空位识别是否与题目语义一致（而非机械匹配下划线）？

### JSON 有效性校验（质量门禁）

**写入 meta.json 前必须完成**：

1. **引号转义**：所有文本字段（`ocr_text`、`answer`、`explanation`、`common_mistakes` 等）中的 ASCII 双引号 `"` 必须转义为 `\"`，或替换为中文智能引号 `""`（推荐后者，更自然）
2. **常见易错字符**：
   - `"人"字形` → `"“人”字形`（中文智能引号）
   - `"西岸"或"东岸"` → `"“西岸”或“东岸”`
   - 题目原文中的引号内容一律用中文智能引号 `""` 包裹
3. **写入后验证**：写入 meta.json 后，**必须读取文件并验证 JSON 有效性**（可用 `node -e "JSON.parse(require('fs').readFileSync('path','utf8'))"` 或 `python3 -c "import json; json.load(open('path'))"` 验证）
4. **无效处理**：如果 JSON 验证失败，不得标记为 `analyzed`，应修复后重试

## 规则

1. **不修改原始图片**：只读取和识别，不对 image 文件做任何改动
2. **保留原始结构**：meta.json 中已有字段不要删除，只更新和新增
3. **批量处理**：如果 pending 题目超过 5 道，提示用户确认是否全部处理
4. **错误处理**：如果某道题目分析失败，标记 `analysis_status: "error"` 并记录原因，继续处理下一道
5. **学科识别**：通过 `meta.json` 中的 `subject` 字段（`geography`/`biology`）判断学科，据此调整分析策略
6. **中文输出**：所有分析内容、OCR 文字、Wiki 内容均使用中文
7. **JSON 有效性**：每次写入 meta.json 后必须验证 JSON 可解析，未通过验证的文件不允许标记为 `analyzed`
